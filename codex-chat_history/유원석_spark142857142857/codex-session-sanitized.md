맞아. **“그냥 Codex/Claude Code에 물어보면 되잖아?”에 답이 없으면 Navigator는 그냥 얇은 래퍼 앱**이 돼.

핵심 차이는 이거야.

| 그냥 Codex/Claude Code | Navigator |
|---|---|
| 사용자가 뭘 물어볼지 알아야 함 | 폴더를 넣으면 전체 구조와 빈틈을 먼저 보여줌 |

| 문서를 읽고 설명 | 실제 작업 목적에 맞는 사용 순서/실행 계획 제시 |

심사 때는 이렇게 말하면 돼.

> “맞아요. Codex에게 하나씩 물어볼 수 있습니다. 그런데 문제는 **무엇을 물어봐야 하는지조차 모르는 상태**예요. Navigator는 파일을 답변하는 대신, 프로젝트의 모든 지침을 인벤토리로 만들고, 지금 하려는 작업에 필요한 스킬과 위험을 먼저 보여줍니다.”

데모도 이 흐름이면 질문을 잘 막을 수 있어.

1. `skills/`, `templates/`, `docs/` 폴더 드롭  
2. “이 프로젝트에는 발표자료 생성, PDF 검토, 배포 스킬이 있고 각각 필요한 입력과 위험은 이것”이라고 지도화  
3. 사용자가 “발표자료 만들어줘” 선택  
4. `presentation` 스킬 추천 + 필요한 자료 체크리스트 + “외부 게시/파일 변경 가능성” 같은 실행 전 확인 화면  
5. 마지막에 **“Codex에게 넘길 실행 프롬프트/계획 생성”**

즉 Codex를 경쟁자로 두지 말고, **Codex를 제대로 쓰게 만드는 인터페이스**로 두는 거지.

다만 MVP에서 “자동 분류 + 예쁜 카드”만 보여주면 반박당할 가능성이 높아. 최소한 아래 중 하나는 꼭 넣는 게 좋아:

- 스킬 간 충돌/중복 탐지
- 작업별 추천 순서
- 필요한 입력 누락 체크
- 위험한 작업의 실행 전 검토(dry-run)
- 팀원이 읽기 쉬운 공유 가능한 스킬 맵

내 취향으론 **“실행 전 검토 + 필요한 입력 체크”**가 제일 강해. 단순히 AI에게 질문하는 행위와 제품의 경계가 가장 선명해져.

| 플랜 | 제공 가치 |
|---|---|

| Pro | 관심 인물·종목 설정, 새 이벤트 알림, 이벤트 전후 비교·CSV/PDF 내보내기 |

> “우리는 매수·매도 신호를 판매하지 않습니다. 시장을 움직일 수 있는 공개 신호를 놓치지 않고, 그 맥락을 조사하는 시간을 줄여줍니다.”

## 2. 크롤링/데이터 관리: “소스별 커넥터 + 출처 추적”

중요한 건 Kaggle을 제품의 실제 데이터 파이프라인으로 쓰지 않는 거야.  
Kaggle은 **해커톤용 과거 데이터**고, 운영 제품은 출처별로 다르게 가져와야 해.

```text
공개 발언 원문
→ 수집
→ 중복 제거·시간대 통일
→ 인물/주제/관련 자산 매핑
→ 시장 데이터 결합
→ 신뢰도 검토 후 이벤트 공개
```

소스별 원칙은 간단해.

- **Powell / Fed**: 연준 공식 발표·연설 아카이브 수집
- **Trump / Truth Social**: 공식 API나 이용 조건이 명확한 아카이브·데이터 제공자 사용
- **Musk / Altman / X**: 운영 단계에서는 X 공식 API 또는 라이선스 데이터 사용
- **해커톤 MVP**: Kaggle·공식 아카이브에서 확보한 과거 데이터만 내장

각 이벤트에는 반드시 아래를 저장해.

```text
원문 URL
원문 게시 시각(UTC)
수집 시각
출처
외부 게시물 ID
데이터 버전
관련 종목 연결 근거
분석 신뢰도
```

### 1. 32,393건이 전체 오케스트레이션된 것처럼 느껴질 수 있음

### 2. AI Research 버튼이 오해를 줄 수 있음

배포 환경에서 버튼을 눌러도 실제 OpenAI가 실행되지 않고 `reviewed_snapshot`을 반환해. 화면에 ‘검토 스냅샷’이라고 표시되긴 하지만 버튼 문구는 여전히 `AI 리서치 실행`이야.

API를 안 쓸 거라면 이 버튼은:

- `증거 리포트 보기`
- `분석 파이프라인 확인`
- `Run evidence audit`

정도로 바꾸는 게 정직해.

### 3. 최신 Signal이 실제로 성숙하지 않음

현재 최신 Trump 신호 5개는 모두 계속 `Pending market session`이야. 시간이 지나도 시장 반응 계산·뉴스 확산·리포트 단계로 자동 전환되지 않아.

계획서의 핵심인:

```text
Initial Signal
→ Amplification Watch
→ Market Reaction
→ Evidence Report
```

가 현재는 시각적 설명이지 실제 상태 머신은 아니야.

### 4. 핵심 자산 확장이 빠짐

BTC, DOGE, SOXX/SMH, GM/F/RIVN은 계획서 후반에서 꽤 중요한 차별화 요소였는데, 초기 확정 자산인 `SPY·QQQ·TSLA·NVDA·MSFT`를 그대로 유지하면서 피벗했어.

### 5. Impact Score 제거는 의도적

계획서에는 Impact Score 유지안이 있지만, 이후 확정 구현안에서 불투명한 단일 점수를 제거하기로 했기 때문에:

- 1D 초과수익률
